# Drive reporter

Covers: scripts/smart-reporter/ scripts/smart_reporter_test.py packaging/smart-reporter/

Drive lifetime writes, and the udisks2 fallback that answers without the reporter, are in [storage](storage.md). This file holds the root side that writes the reports, and its two install routes.

## The drive reporter

`scripts/smart-reporter/` holds the root side of drive lifetime writes: `vsys-smart-report`, a oneshot service and an hourly timer that run it, and the tmpfiles line that creates `/run/smartctl` at boot, the default `smartDir`. The reporter writes `smartctl -i -A` output to `<name>.txt` for each `/sys/block` device with a drive behind it, under a hidden name renamed whole, and skips the loop, memory, optical and floppy devices vsys draws no row for. A nonzero smartctl status still leaves the report, because smartctl sets status bits for a failing drive. Each drive's query runs under `timeout`, `SMARTCTL_TIMEOUT` seconds by default 20, so a stalled query or a wedged USB bridge costs only that drive's report, read as lifetime writes unknown, and not the reports after it; the service's `TimeoutStartSec` is sized for the whole run the same way, and raising `SMARTCTL_TIMEOUT` by D needs `TimeoutStartSec` raised by D times the drive count, not by D. A missing `timeout` command exits the reporter loudly instead of masking every report, and so does a missing smartctl, which a package leaves possible because smartmontools is only an optional dependency: it writes no report, so udisks2 still answers. `install` fetches the four files from a tagged release, `VSYS_VERSION` or the latest, and checks each against that release's `SHA256SUMS`. It puts them in place under names of vsys's own, starts the timer, and installs nothing when smartctl or timeout is missing, a download fails, or a checksum is missing or does not match. `.github/workflows/release.yml` checksums the four files into `SHA256SUMS`, and `test_the_release_checksums_every_file_the_installer_fetches` in `scripts/smart_reporter_test.py` holds the installer's file list to the files beside it and to the release's checksum list. vsys never runs it: Storage and Settings offer the line to copy. The vsys and vsys-git packages are the other route. They install the four through `packaging/vsys-runtime-files.txt`: the script at `/usr/lib/vsys/scripts/smart-reporter/vsys-smart-report`, the timer and the service under `/usr/lib/systemd/system/`, and the tmpfiles line at `/usr/lib/tmpfiles.d/vsys-smart.conf`. The service is `packaging/smart-reporter/vsys-smart-report.service`, the installer's service with its `ExecStart=` naming that script. `scripts/package_file_list_check.py` refuses a manifest without the four, and a packaged service that differs from the installer's in any other line; `test_smart_service_is_the_installer_service_running_the_packaged_reporter` in `scripts/package_file_list_check_test.py` holds it. The names match the installer's `/etc` copies, so where both are present systemd reads those and one reporter runs. A package enables no timer. Where the packaged timer is installed, the collector asks `systemctl is-enabled` for `vsys-smart-report.timer`, as [the scrub reporter](scrub-reporter.md) reads its timers. Where systemd answers `disabled`, Storage and Settings offer `sudo systemctl enable --now vsys-smart-report.timer` in place of the install line. Any other answer offers nothing, and so does a timer or an answer that could not be read. `src/collect/scrub-timers.test.ts` and `src/ui/settings.test.ts` check both.

The invariants that hold the report format and its precedence over udisks2, and the tests that enforce them, are in [storage § Invariants](storage.md#invariants).
