# Lanes and processes

Covers: src/model/lanes.ts src/model/naming.ts src/model/launcher.ts src/model/launcher.test.ts src/model/scopes.ts src/model/alerts.ts src/model/alerts.test.ts src/model/types.ts src/collect/procs.ts src/collect/tmux.ts src/collect/io.ts src/collect/io.test.ts src/collect/cgroups.ts src/model/lanes.test.ts src/collect/collector.test.ts

A lane is a watched scope, or a group an agent or a resource alarm made worth watching. The collector reads the processes; the model derives the lane, its name, its launch trail and the alert rules that fire on it. [agent-tools.md](agent-tools.md) owns which processes are agent tools. [lanes-tmux.md](lanes-tmux.md) owns how a lane's tmux pane is resolved and whether it is the pane vsys draws in.

## Boundaries

- `unitLabel()` in `src/model/naming.ts` is the only place a systemd unit name becomes a name a screen shows. It drops the `app-` launcher prefix, the unit suffix and the generated field systemd adds for uniqueness, and decodes `\xNN` escapes.
- `distinctNames()` in `src/model/naming.ts` is the only rule for names that repeat, and its one caller is Resources. Lanes do not use it: a lane name is never added to, and two lanes resolving to one name are told apart by the process id column beside them.
- `laneText()` in `src/model/naming.ts` names a lane in prose, where there is no column to carry the process id: the name, then `PID` and the process leading it, or the name alone for a lane leading none.
- A lane name joins the configured parts in the configured order and leaves out a part with no value. `pane` is still accepted as a part so a stored config keeps loading, but it composes nothing.
- Every tmux read runs through `spawnText()` in `src/collect/io.ts`, bounded by `tmuxTimeoutMs` so a wedged server costs one call rather than every future sample, and the call's exit status is returned unjudged; the kernel log search shares `spawnText()`, bounded by its own `kernelLogTimeoutMs`, because journalctl's exit 1 is an answer. `spawnText()` escalates from SIGTERM to SIGKILL after `killGraceMs`, so a child that traps or ignores SIGTERM is still bounded.
- `sliceCompared()` in `src/model/lanes.ts` decides whether agents are compared against the agent slice at all. Only a probe that found the slice absent or masked stops the comparison, since systemd never starts either. A slice vsys could not read and a sample recorded before the probe keep it, so a failed read never silences an escaped agent. Where the slice is absent or masked, every agent is a lane with its own group's resources, and none is escaped.
- `probeAgentSlice()` in `src/collect/capabilities.ts` reads the slice every sample, because systemd starts a slice when the first unit is placed in it. A group of the slice's name anywhere in the sample's tree is the slice. Otherwise the path systemd gives the name decides: `slicePath()` nests a dashed name in the slice it prefixes. Where that path does not exist, a unit file or drop-in directory for the slice in the user manager's unit directories makes it present all the same ([D009](../decisions/D009-agent-slice-unit-file.md)), so a defined slice nothing has started yet still holds agents to it. The first directory in the user manager's order that holds a unit file decides, as it does for systemd, and a unit file there that resolves to `/dev/null` reads `masked`, a failure of its own: Settings says the slice is masked and offers no line, because `systemctl` refuses to set a property on a masked unit. Otherwise only a slice with no unit file and no drop-in is absent, and a path that exists but cannot be read leaves it unknown.
- `launcherKnown()` in `src/model/launcher.ts` decides whether a card may speak of a launcher: the slice is present and `capMarkers` names at least one marker. A sample recorded before the slice probe counts the slice present, as `sliceCompared()` does, so its card reads as it did when it was recorded. Without both, a missing marker says nothing about how an agent started, so the unconfined card states the slice limit and gives no launcher conclusion.
- `scopeMain()` in `src/model/scopes.ts` picks a scope's main process: the oldest member whose parent sits outside the scope.
- A group-less lane carries its member's absolute kernel cgroup path. `coveringGroup()` in `src/model/lanes.ts` resolves it to the configured group whose `kernelPath` is it or its nearest ancestor before `effectiveMax()` runs; none found, root included, leaves the cap unknown.
- `launcherTrail()` in `src/model/launcher.ts` reads the facts of one process and states no prose: the scope it names is the unit name, not a phrase. `launcherCopy()` writes the prose a card draws, and is the only place that writes it: it groups the trails by the four facts a sentence states, keyed on the whole cgroup path, and gives each group a conclusion and an ancestor clause the card can drop on its own, taken from a member whose ancestors the sample still holds. `launcherTally()` writes the one line a card too narrow for a sentence can hold: every group counted under its own conclusion.

## Invariants

1. An escaped agent is a configured tool outside the configured agent slice, on a machine that has the slice, decided once by `escaped()`. `src/collect/collector.test.ts` checks an escaped agent against an inherited cap, and two agents with the slice present and absent; `src/model/lanes.test.ts` tables the comparison for a present, unreadable, unrecorded, absent and masked slice; `src/collect/capabilities.test.ts` tables the probe.
2. The environment of an escaped agent is read from that agent, not from its scope's main process, and scope launch metadata belongs to the scope's main process. `src/collect/collector.test.ts` checks an agent child of a pane shell and a wrapper with an agent child.
3. A launcher trail states the ancestors and their cgroups, the confinement markers and any PATH prefix, and names a repeated neighbour in the chain once. Markers with the wrong cgroup mean a shadowed launcher, their absence a bare launch, and an unreadable environment neither. `src/model/launcher.test.ts` checks all three.
4. One sentence covers every process agreeing on all four facts it states: the conclusion, the cgroup, the markers set on them and the PATH entries ahead of the login shell's own. It names the markers once, the scope once with the count of processes in it, and the ancestors once for an example process it names by PID. `src/model/launcher.test.ts` groups six processes in one scope, ten over two, and pairs differing only by marker set, only by PATH prefix, and only by the slice above a scope of one unit name.
5. A lane name joins the configured parts in the configured order and leaves out a part with no value. `src/model/naming.test.ts` checks the order; `src/model/lanes.test.ts` checks two accounts in one worktree and a lane naming no account.
6. No lane name carries a pane address or a disambiguator, and no unit name reaches a screen carrying a `\xNN` escape, the `app-` prefix or a `.scope` suffix. `src/model/naming.test.ts` checks the unit forms; `src/model/lanes.test.ts` checks that a name holds no separator the server gave it.
7. No two resource groups in one sample render the same name, and hiding the idle rows never renames one. `src/ui/resources.test.tsx` checks the separation and the filtered list.
8. Per-lane page cache, I/O rates, CPU share and cgroup weight stay unknown when the kernel did not report them, and an unread cgroup tree leaves the effective memory cap unknown rather than unlimited. A lane takes its age from its oldest member and its resident memory from the sum over its members, so a lane with no member read on the sample has an unknown age and resident memory and no main process, and the Agents list and agent header draw each as a gap. The JSON and Markdown export write that lane's main process as unknown, judged by `memberless()` in `src/model/lanes.ts`. Its CPU and swap come from its cgroup first and stay unknown only when the cgroup did not report them either. `src/model/lanes.test.ts` checks a group with no counters, a lane with no covering group, a group-less lane both inside and outside the configured root, the age and memory of a lane with members, and a watched scope with neither group counters nor a readable member; `src/ui/format.test.ts` checks the unknown age in the list, `src/ui/agent.test.tsx` checks the PID and age in the header, and `src/model/export.test.ts` checks the export.
9. A cgroup limit file holds a number or the word max, so a file that could not be read leaves the effective cap known only when every covering ancestor was read. `src/collect/collector.test.ts` removes an ancestor's `memory.max`.
10. A blocked lane counts its tasks in uninterruptible wait and names storage or memory by the higher stall share, naming neither when the pressure is unknown. `src/model/lanes.test.ts` checks both resources and unknown pressure.
11. Process environment caching uses the PID with its start time, so a reused PID is a different process. `src/collect/collector.test.ts` exercises PID reuse and environment selection.
12. When a PID appears in sibling scope lists, its process membership file selects the row. `src/collect/collector.test.ts` checks that fallback.
13. Each new escaped agent emits its own alert even inside an already alarmed scope, and every rule clears before it rearms. `src/model/alerts.test.ts` checks process identity and rearming.

Invariants 14 to 16, on tmux pane resolution, are in [lanes-tmux.md](lanes-tmux.md).

17. The unconfined card names a launcher only where the slice is present and confinement markers are configured. `src/ui/attention.test.ts` checks a present slice with and without markers, an unreadable slice and a sample recorded before the probe.
18. A tmux or journalctl read that stalls, including one whose child ignores SIGTERM, is killed rather than blocking every future sample: `spawnText()` sends SIGTERM at its deadline and escalates to SIGKILL after `killGraceMs` for a child still running. `src/collect/io.test.ts` kills a real SIGTERM-resistant child and checks the escalation.
