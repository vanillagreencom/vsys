# Agent warden notifications

Covers: warden/agent-warden (notify-send, episodes, --status), warden/agent_warden_notify_test.py

The warden sends desktop notices through `notify-send` only when no consumer owns them. A consumer owns notices by touching `$XDG_RUNTIME_DIR/agent-warden/notifier`. The warden trusts that heartbeat while its mtime is under 120 s old, and treats an absent, unreadable or far-future heartbeat as stale. A consumer should touch it every 60 s. `warden/agent-warden --selftest` covers the heartbeat rows. `warden/agent_warden_notify_test.py` covers the module path and event suppression in `test_notifier_heartbeat_rows`, `test_notifier_fresh_stale_mutant_fails` and `test_notice_handoff_rows`.

The fallback notifier records open episodes in `state.json` under `episodes`. Each key has the shape `<kind>:<scope>`. Each value carries `kind`, `scope`, `since` and `notified`. Near-cap episodes use kind `tasks` or `memory` and scope the lane unit. Headroom episodes use kind `not-moving` and scope `agents.slice`. Move-failure episodes use kind `move-failure` and scope the root pid plus start time. The warden sends one successful notice while an episode is open. A failed `notify-send` leaves the episode pending, so the next tick retries it. It sends again only after the condition clears and opens again. Restricted `AGENT_WARDEN_ONLY` runs clear no episode, because they do not evaluate the whole slice. Headroom episodes stay open on every tick where headroom blocks a move, even before the skip threshold allows a notice. Near-cap episodes clear only after a below-threshold read for that scope and kind, or a complete listing shows the scope gone. `warden/agent-warden --selftest` covers one notice per episode. Rows and controls in `warden/agent_warden_notify_test.py`: `test_episode_dedupe_rows`, `test_failed_episode_delivery_stays_pending`, `test_run_move_failure_episode_rows`, `test_restricted_run_preserves_episodes`, `test_not_moving_episode_lifetime_rows`, `test_move_condition_recovery_clears_episode_rows`, `test_near_cap_unknown_keeps_episode_rows`, `test_near_cap_listing_failure_keeps_episode_rows`, `test_failed_delivery_pending_mutant_fails`, `test_run_headroom_preserves_move_failure_mutant_fails`, `test_restricted_run_clear_mutant_fails`, `test_restricted_run_final_clear_mutant_fails`, `test_no_moves_clear_mutant_fails`, `test_final_selective_clear_mutant_fails`, `test_not_moving_seen_mutant_fails`, `test_near_cap_unknown_clear_mutant_fails` and `test_near_cap_listing_failure_clear_mutant_fails`.

A fresh consumer suppresses event notices too. Reap and move notices still log their journal lines. The warden logs `notice left to consumer` for a notice that the heartbeat suppresses. It logs `notify-send failed` when its fallback notice cannot be delivered. `warden/agent_warden_notify_test.py` covers the suppression guard and delivery result in `test_notification_handoff_mutant_fails`, `test_notify_send_result_rows` and `test_notify_send_exit_mutant_fails`.

`--status` reads `state.json` without a lock or write. It creates no state directory or lock file. A missing or invalid state file reads as the default state. An unreadable existing state file exits non-zero and prints `agent-warden: state=unreadable`. Selftest heartbeat rows use `tempfile.TemporaryDirectory()` outside `$XDG_RUNTIME_DIR/agent-warden`. `warden/agent_warden_notify_test.py` covers this in `test_status_read_only_subprocess_rows`, `test_status_absent_directory_rows`, `test_status_unreadable_state_fails`, `test_status_read_only_mutant_fails`, `test_status_directory_creation_mutant_fails`, `test_status_rewrite_mutant_fails`, `test_status_unreadable_state_mutant_fails`, `test_selftest_subprocess_leaves_no_state_dir` and `test_selftest_state_dir_mutant_fails`.
