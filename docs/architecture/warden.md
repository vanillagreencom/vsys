# Warden boundaries

Read before changing what the optional warden under `warden/` moves, leaves alone, caps, reaps or reports, how it is installed, or what a package ships beside the binary.

## The approach

The optional warden corrects placement independently of the dashboard under [D004](../decisions/D004-warden-separate-component.md). Keep automatic correction in `warden/`, with the dashboard dispatching installation through `src/warden.ts`. Packages ship the payload declared by `packaging/vsys-runtime-files.txt`; only an explicit install enables the timer.

## Why

Correction must remain an explicit user choice. Installer ownership checks prevent overwriting dotfile-managed or foreign units.

## Rules

Review holds boundaries without a named check.

- Do move only the three classes: an escaped launch, which carries `AGENT_CONFINE=1` and runs outside the slice; an unconfined agent or build tool the classification data confirms; and a nested session that shares a scope and needs a CPU share of its own. Re-read identity, cgroup and classification through a pidfd before each move. `warden/agent_warden_test.py` and the `--selftest` mode cover the planning rules.
- Do leave a contained job unit alone: one matching `AGENT_WARDEN_JOB_UNITS`, or one outside the slice whose own cgroup carries a real memory, swap, CPU, I/O or cpuset limit. `pids.max` alone is not a limit, because systemd sets a default task limit on every unit. `contained_unit()` is the rule.
- Do confirm an agent's name as [lanes.md](lanes.md) states, through `Proc.is_agent`, and judge whether a scope holds a live agent through `Proc.is_named_agent`, the name alone.
- Do reap only an orphaned `.scope` under the slice: every member lost its launcher, no member holds a terminal, none is a live agent, no live external parent holds it, the grace has passed, and `scope_harm()` holds on two ticks. Grace and harm history belong to one cgroup directory instance. A replacement directory starts fresh grace; an unreadable identity discards history and prevents a stop. Check that identity before and after the membership recheck. An incomplete child-cgroup enumeration prevents a stop. An unread `memory.stat` never makes a scope harmful. `warden/agent_warden_orphan_test.py` checks these boundaries.
- Do remove a lane's scratch directory under `AGENT_TMPDIR`, or under agent-confine's default `${XDG_CACHE_HOME:-~/.cache}/agents/tmp` where `AGENT_TMPDIR` names another parent, only once its scope is gone and no process keeps it. Scan every process again before each attempt, so a process that started during an earlier removal in the pass is read. A process keeps a directory when its TMPDIR or its current directory names that directory or a descendant of it, whichever of the two could be read. A process that exited since the scan keeps nothing.
- Do judge unread processes in both holder passes through `_unread_may_hold()`. A desktop unit keeps nothing through unread evidence. An unread process also keeps nothing through that evidence when its parent is live, is not PID 1 and has another real uid. Recheck the process's identity and parent pid after the scan, and the parent's start identity, live state and real uid across that read. A changed, exited or unreadable parent keeps the old rule. Never judge this exemption by a name, comm, argv or a whole login session: readable paths and unread same-user descendants still count. This accepts the limit that a test's non-dumpable sudo/setuid child of another user can lose an unread held directory. `warden/agent_warden_leftovers_test.py` and `warden/agent_warden_scratch_test.py` check the shared rule.
- Do keep, in the scratch pass, for an unread process admitted by the shared rule, every directory no readable process names. A process is unread there when its environment or current directory cannot be read. A process in a live lane scope can keep less: its own directory stays while the scope is live, and a readable member of that scope stands in for its unread members, because the rule reads the member's TMPDIR and current directory as they are now, not as the launch handed them down. `warden/agent_warden_scratch_test.py` checks the unread-process rules.
- Do accept this limit in the scratch pass: an unread process in a live lane scope with a readable member loses another gone lane's directory while it runs, when its TMPDIR or current directory names that directory and no readable member holds it now. That needs a lane launched from inside another lane's directory, a `mkdir` collision, or a process that entered the directory before it became unreadable; that lane ended; and every readable member moved off the path. No record owns this loss; this paragraph holds it.
- Do attempt at most `SCRATCH_REMOVALS_PER_PASS` scratch removals in a pass, failed removals included, and drain a backlog over later ticks. The cap bounds the count of attempts, not the time one removal or one tick takes. The measurement evidence is on [VSY-218](https://linear.app/vanillagreen/issue/VSY-218). `warden/agent_warden_scratch_test.py` covers the rule.
- Do remove a test world only when a pattern in `AGENT_WARDEN_TEST_WORLDS` matches it, it is older than `AGENT_WARDEN_TEST_AGE`, and no process keeps it. A candidate is a real directory this user owns, never a symlink, a mount point or a directory with one under it, and never the root, `HOME`, the runtime directory, a scratch parent or an ancestor of one. A readable process keeps a world when the world's path, followed by `/`, the end or a character no file name continues with, occurs in its current directory, its executable, an open file, an argv element or an environment value. An absolute path in an argv element or an environment entry, its part after `=` or a `:`-separated piece of either, is also read resolved through symlinks, so a TMPDIR that reaches the world through a symlinked directory keeps it. Any unread process this user runs admitted by the shared rule keeps every world, with no lane exception: a test creates its world after the lane launched. A process is unread here when any of those reads fails and it has not exited. Scan every process again before each attempt, as the scratch pass does. `warden/agent_warden_leftovers_test.py` checks these boundaries.
- Do attempt at most `TEST_WORLD_REMOVALS_PER_PASS` test-world removals in a pass, apart from the scratch cap, so neither backlog starves the other. Failed attempts count, and later ticks drain the backlog. A count cap does not bound wall time. The measurement evidence is on [VSY-245](https://linear.app/vanillagreen/issue/VSY-245).
- Do reset a failed unit only when systemd reports it transient, its `FragmentPath` is `$XDG_RUNTIME_DIR/systemd/transient/<unit name>`, and its `StateChangeTimestampMonotonic` is older than `AGENT_WARDEN_TEST_AGE`. Reset it through the manager's `ResetFailedUnit`, at most `FAILED_UNIT_RESETS_PER_PASS` a pass, within `FAILED_UNIT_PASS_SECONDS` of bus time a pass, before any move. Leave alone a unit with a file anywhere else and a unit whose properties cannot be read, and never start or stop a unit in this pass. `warden/agent_warden_leftovers_test.py` checks these boundaries.
- Do report an old test process and never signal it: one past `AGENT_WARDEN_TEST_AGE` with no terminal, whose argv element, its part after `=` or a `:`-separated piece of either, as written or resolved through symlinks, lies in a directory a test-world pattern matches, whether or not the directory still exists. Group each by the basename of the main working tree of the repository its current directory lies in, so every worktree of one repository shares an id. `warden/agent_warden_leftovers_test.py` checks these boundaries.
- Do read every tunable through `env_number()` in `warden/agent-warden`: an empty value is unset, and a value outside its format is logged and the default used, so a bad value never stops a tick. `warden/agent_warden_settings_test.py` covers the variables and their formats.
- Do leave `AGENT_WARDEN_TEST_WORLDS` empty by default, so no repository's pattern is built in. An operator sets it for the installed timer's service in a `systemctl --user edit agent-warden.service` drop-in, for example `Environment=AGENT_WARDEN_TEST_WORLDS=/tmp/vgshell-world.*`. A pattern is absolute, has wildcards only in its last component, and opens that component with at least four literal characters; one bad pattern turns the whole list off.
- Do write `status.json` with numbers and ids only, null for a reading that could not be taken, through a temporary file and a rename. Its `leftovers` object counts test worlds, failed transient units and old test processes, each null when its pass raised, could not read every input, or has no pattern to read. `status_errors()` and `warden/agent_warden_status_test.py` check the status contract.
- Do send a desktop notice only when no consumer owns them, judged by the heartbeat file under the runtime directory, and send one notice per episode. `warden/agent_warden_notify_test.py` covers the handoff and the episodes.
- Do refuse the whole install when any target is a symlink or an unmarked file, when a unit or data directory is itself a symlink, or when a target cannot be read. A marked file is ours and can be rewritten. `warden/install_test.py` covers foreign, unreadable and linked targets.
- Do overwrite the copied data file only when it is absent or its hash matches one recorded in the marked service unit, and record both the new and the installed hash during an upgrade so an interrupted write can be retried.
- Do make `uninstall` remove only marked files and a data copy whose hash matches, stop only a marked service, and leave `agents.slice` and every running scope alone.
- Do make `status` read-only, and fail it on any read that could not be taken.
- Do add a shipped file to `packaging/vsys-runtime-files.txt`. `scripts/package_file_list_check.py` holds the payload, the modes, the reporter rows and the rule that no package installs or enables a user unit, and `scripts/package_file_list_check_test.py` runs each PKGBUILD's `package()`.
- Never kill an individual process, and never stop a live session.
- Never move a process already inside the slice as a descendant, and never move a desktop app or an excluded helper.
- Never fail open on the slice's memory counters: an absent slice is empty headroom, so the first move can create it, and an existing slice with unreadable counters stops every move.
- Never write `status.json` from `--status`, `--selftest` or a restricted `AGENT_WARDEN_ONLY` run.
- Never write, overwrite or remove the local overlay `~/.config/vsys/agent-tools.json` from the installer.
- Never install under `/usr/lib/systemd/user`, and never preset or enable a unit from a package.
- Never strip the compiled binary in a package. Stripping removes Bun's appended bundle, so both PKGBUILDs set `!strip` and `!debug`.

## The canonical example

Copy `contained_unit()` in `warden/agent-warden` for one shared safety judgment. Copy the `MARKER` ownership check in `warden/install` before changing a file the installer may own.

## Revisit when

A Bun foreign-function interface port can call pidfd and libsystemd with the same safety ([D004](../decisions/D004-warden-separate-component.md)), or the dashboard must own an automatic correction under a new explicit promise. Packaging generates per-distribution units, or systemd offers a user-unit ownership record the marker duplicates.
