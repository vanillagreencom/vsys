# Storage check memory

Covers: src/collect/btrfs.ts src/collect/btrfs.test.ts src/collect/collector.test.ts src/collect/errors.test.ts src/collect/scrub.test.ts src/model/integrity.ts src/model/integrity.test.ts src/model/verdict.test.ts src/ui/integrity.test.ts src/ui/attention.test.ts

The memory of a filesystem's last finished check, and what counter growth a finished check accounts for. The sources, the boundaries these invariants rest on and invariants 1 to 13 are in [storage integrity](storage-integrity.md). The numbers continue from that file.

## Invariants

14. A scrub that stops early, a report gone from disk, or a finished report that moved backward in time (a restored older report), never erases the memory of an earlier one that finished, its outcome included: `integrity()` treats a finished report as authoritative unless its own `startedAt` is read and known to be older than the remembered check's; an unread `startedAt` stays authoritative, and only a known-older one defers to that memory exactly as a stopped-early report does. `checkAge`, the state ladder's new-errors and damaged/healthy/stale evaluation, and the new-errors card's last-check age all keep naming the last finished report's age and damage state, and only a later finished report moves that memory forward. `scrubFoundDamage()` in `src/collect/btrfs.ts` is the one rule for whether a finished scrub's own numbers count as damage, and both the live report and a remembered one are judged by it, so a check that is only remembered reads no differently from one still live. The ladder judges `never-checked` against whether any finished check is on record at all, current or remembered, never against whether the current report is itself null or finished, so a remembered check keeps a filesystem out of `never-checked` and lets it read `healthy` or `stale` exactly as it would with that report still live — unless the remembered check found damage, which reads `damaged` instead and never `healthy` or `stale`, whatever the current report says. A kernel-log failure dated before the remembered check is already covered by it and is excluded from `logged` the same way a failure before a live finished report is. The memory is this process's own and survives a settings save rebuilding the collector, the same way the kernel log's cursor does, through `FinishedScrubMemory` (`src/collect/btrfs.ts`): `createCollector()` hands the replacement the replaced collector's own instance rather than a copy, so a scrub still finishing on the predecessor when the replacement is built, and found damaged only after that handoff, still lands in the one memory both collectors read. `src/collect/btrfs.test.ts` overwrites a finished report with one that stops early, reads the memory back, checks a stale replayed report never moves it backward, and checks a damaged outcome survives the same way a clean one does; `src/model/integrity.test.ts` checks the state and age `integrity()` derives from it, including a stopped-early report, one gone entirely, a remembered damaged check that a later stopped-early or missing report must not clear, a finished report that started before the remembered check and must not outrank it, an undated finished report that still speaks for its own damage, and a logged failure on each side of the remembered time; `src/ui/integrity.test.ts` checks that a superseded finished report reads as superseded rather than never finished, that `blocksText` and `noDamageText` name what a remembered check found rather than claiming no report, saying the current report is unavailable rather than gone whether it was never written or exists unreadable and unmatched by fsid, except when their `scrub` capability says this sample's listing failed, which they report instead; `src/ui/attention.test.ts` checks the new-errors card still names that age rather than saying no check has ever run; `src/collect/collector.test.ts` checks a settings-rebuilt collector, built the way `Session.configure()` builds one, keeps the memory through the real `Collector.lastFinishedScrub` getter, and that a finish landing on the predecessor only after the rebuild still reaches the replacement because the two share that one `FinishedScrubMemory` rather than each holding a copy.
15. A `damaged` state reached only through a remembered check, its current report stopped early, gone, or itself finished but older than the remembered check, carries no address data: `damageCounts()` returns every count null rather than zero, which is the reading a report that actually named none would give, and the damage card tells the reader its last report naming the damage is no longer available instead of claiming the damage sits in free space or a deleted file. `src/model/integrity.test.ts` checks `damageCounts()` against a remembered-only damaged state; `src/ui/attention.test.ts` checks the card's words and its next step, both for a stopped-early report and one gone entirely.
16. Counter growth a finished check accounts for is not new: `integrity()` reads it by the check's own outcome, from the live report or the remembered one. Growth whose bound came after the check ended, growth larger than it counted, and a report with no readable `Duration` or count stay `new-errors`, as does growth from a reading on disk unless that reading came by the check's start and the growth equals its csum count, and the new-errors card names only growth and logged failures `integrity()` judged new. `src/model/integrity.test.ts` holds one row per case and the remembered check; `src/collect/btrfs.test.ts` collects a scrub that corrected three errors, overwrites it with one that stops early, and grows the counter after a reading past its end, then holds one row per process history: growth first seen after the scrub by the process that read before it, growth seen during the scrub and kept covered by a new process, then new growth a new process sees a week later, and a baseline saved before a scrub with growth a new process sees days later, the last two `new-errors`, then from a baseline saved before the scrub its csum count `healthy` and one more `new-errors`, and from one after its start `new-errors`; `src/collect/errors.test.ts` checks the previous reading's time, from a reading that changed nothing and across a restart, and none for growth after a reading from disk or one a merge took from another process, which keep that reading's time instead unless the record has none; `src/model/verdict.test.ts` checks the card names a new logged failure and not the covered growth; `src/collect/scrub.test.ts` parses `Duration` and the csum count.
